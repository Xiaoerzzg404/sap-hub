# 01｜产品蓝图 v2（嵌入 sap-hub 生态）

## 一、定位

SAPKB 是 **sap-hub 生态里的“外部 SAP 内容采集与知识资产层”**，服务于：
SAP 顾问（你本人）· SAP 自媒体选题 · SAP 培训素材 · 项目 Q&A 支撑。

它**不是**：违规爬虫、孤岛 web 系统、SAP_FUZHKB 的替代品。
它**是**：把外部公开/已授权 SAP 内容，沉淀成可检索、可问答、可复用、可追溯的**参考层知识库**。

## 二、SAPKB 与 SAP_FUZHKB 的关系（最重要的一张图）

```text
         ┌──────────────────────────────────────────────┐
         │            sap-hub 生态                        │
         │                                                │
         │  ┌────────────────┐      ┌──────────────────┐  │
         │  │  SAP_FUZHKB     │      │     SAPKB         │  │
         │  │  自有权威库      │      │   外部采集参考库   │  │
         │  │  置信层：HIGH    │ ◀──  │   置信层：REF      │  │
         │  │  67 流程 +       │ 单向 │   知乎/公众号/CSDN │  │
         │  │  15_Config v3.1 │ 引用 │   + 已购授权内容    │  │
         │  └────────────────┘      └──────────────────┘  │
         │      你亲手验证的            外部采集的，需存疑     │
         │      可直接对客户用          只能当线索和原料       │
         └──────────────────────────────────────────────┘
```

**铁律**：信息只能从 SAPKB（参考层）**单向流向** SAP_FUZHKB（权威层），且必须经你或 Agent 显式确认后改写沉淀；
反向不可——FUZHKB 的权威内容不下放到采集库。这条直接继承你既有原则“外部 AI 输出当原料，不当平行权威”。

## 四、三条核心工作流

### 工作流 A：发现并合规收录一篇 CSDN/知乎 SAP 文章

```text
关键词/订阅源 → 既有采集通道(RSSHub/WeWe RSS/手动) 取得「线索」
  → Compliance Gate 判定 import_mode（默认 metadata_only）
  → 入 SAPKB documents（content_status=metadata_saved）
  → 自动摘要 + SAP 实体识别 + 自动标签 + 去重
  → 若你已购授权/手动确认 → 升级为 fulltext，写入 Obsidian 正文
  → 自审 + 三方审 → 进知识库（chunked/embedded）
```

### 工作流 B：手动保存（公众号/付费已购）

```text
你在 App 里读到好文 → 浏览器剪藏/复制正文 + 填写 rights_status
  → 若 license_purchased：上传发票/许可截图到 licenses 表
  → 清洗转 Markdown → 进流水线 → 按作者/专栏归档
```

### 工作流 C：本地问答（带来源）

```text
提问（如：F110 付款方式与银行确定的关系）
  → Query Analyzer 识别模块/tcode/表
  → 混合检索（FTS5 + 向量）→ Reranker
  → 答案生成 → Citation Guard（必须引本地来源）
  → 标注：哪些来自 FUZHKB(权威)、哪些来自 SAPKB(参考，需验证)
```

> 注意工作流 C 的最后一步：答案要**区分置信层**。来自权威库的可直接信，来自采集库的标“需验证”。

## 五、功能优先级（MVP 只做粗体）

- **P0 采集→入库→去重→标签**（复用既有去重引擎）
- **P0 SAP 实体识别 + 自动摘要**
- **P0 本地混合检索 + RAG 问答（带引用与置信层标注）**
- P1 专栏/作者镜像（需求 8）
- P1 已购授权凭证留存（需求 5 版权部分）
- P1 双审 gate 落盘（需求 10）
- P2 自动增长（backlog harvester）
- P2 本地模型增强 / LoRA 评估

## 六、产品原则（继承 v1 + 新增）

1. 合规优先：宁可少收，不违规批量搬。
2. 来源可追溯：每条知识有来源、时间、授权状态、处理日志。
3. 本地优先：默认本地，项目机密不上云。
4. 摘要优先、全文慎重：全文需授权。
5. **置信分层（新）**：采集层 ≠ 权威层，问答必须标注来源置信。
6. **复用优先（新）**：能用 sap-hub 既有组件就不重造。
7. AI 不直接信任：所有 Agent 产出过自审 + 三方审。
8. 工具化、可迭代优先。
