## 0. 一句话结论

A 不是展示站，是一套已成形的 Next.js 训练工作台（24 课 + 五步训练 + 录音云链路 + 多角色 RBAC + 讲师/admin 面）。
它缺的不是「从零搭」，而是**把训练闭环真正闭上**：动作级完成度、课末收束、讲师点评回灌学员端、跨设备续学。
本轮（Ryan 2026-06-10 选定）先做**第一阶段：训练闭环 + UX 打磨**。

## 1. A 现状审计（基于代码实读，非推测）

### 1.1 学员训练主线（`/courses/lessons/[lessonId]`）
五步训练壳 `LessonStepShell` + `LessonStepper`，对应五动作：
术语预热(听读) → 句型听读 → Shadowing+替换 → 30 秒输出 → 60 秒+RolePlay+作业。结构完整、移动端栅格已做。

### 1.2 专项口语工具（`/speaking/*`）
shadowing / repeat-player / recording / self-training / micro-training(30s) / consultant-output(60s) 六个工具页齐备。

### 1.3 录音云链路
`RecordingPanel` 走 `sign → PUT → PATCH`，软删除 + signed 回放 + IndexedDB fallback，API 与 `cron/cleanup-recordings` 齐备。

### 1.4 权限与数据
credentials 登录 + 多角色 RBAC（`user_roles`）+ 邀请码注册；`progress_events` 服务端事件 + localStorage fallback；
讲师反馈表 `teacher_feedback` + `/api/teacher/recordings/[id]/feedback` + `/review` 已存在。

### 1.5 讲师/Admin
`/teacher`（教练台 / 录音复核 / 术语复核 / 反馈 upsert）、`/admin`（运维监控台）已上线。

## 2. 第一阶段要补的具体缺口（训练闭环 + UX）

| # | 缺口（代码实证） | 现状 | 目标 |
|---|---|---|---|
| G1 | **RolePlay 讲师点评是死占位** | `components/speaking/RolePlayRecorder.tsx` 末尾硬编码「讲师点评占位：可接入后端后显示…」 | 接已存在的 `teacher_feedback`，按本条录音 id 拉取并内联显示评分/纠错/重录建议 |
| G2 | **步骤完成是「位置式」非「动作式」** | `LessonStepper` 仅凭 `index < stepIndex` 判定变绿，没真正做动作也算完成 | 引入动作级完成信号（听够 N 次 / 录音已保存 / 作业已提交）驱动步骤勾选 |
| G3 | **课末不收束** | 最后一步只有「下一课」链接，无「标记本课完成」与本课小结 | 加课末收束卡：写 `lesson_completed` 事件 + 本课产出小结（录了几段 / 五步完成度），再引导下一课 |
| G4 | **续学只到「步骤位置」级** | 更正：`setLessonStep` 已发 `lesson_step_advanced` 服务端事件，`loadProgress` 从事件重建——**步骤位置已跨设备同步**。真正缺的是「动作级完成」尚未进事件（依赖 G2）、且 `/me` 没有「继续上次」显式入口 | G2 落地后把动作完成同步事件；`/me` 增「继续上次：第 N 步」入口 |
| G5 | **空/错/成 三态不齐** | drills/roleplay 有空态；micro/consultant/shadowing 数组空时只剩标题 | 统一补空态、录音失败态、保存成功态，符合护栏「每个主流程五态齐全」 |
| G6 | **回流页未显式收口** | `/me`、`/dashboard` 有进度，但课末完成事件尚未驱动「下一课推荐 + 弱项回看」 | G3/G4 落地后，把完成度回灌 `/me` 与 `/dashboard` 推荐位 |

## 3. A vs B 显式差异（结论版，B = 公网历史静态版）

B 是已发布公网版的静态快照（17 路由抓取成功），**无动态后端**：无登录态、无录音写入、无进度、无讲师反馈、无 admin（公网 `/admin` 返回 404）。
A 相对 B 的真实增量是「整套动态训练后端」：登录/RBAC、五步训练壳、录音云链路、进度事件、讲师反馈、运维台。
→ B 的价值是对照与回退，不是并行产品；A 是唯一主开发线。**第一阶段只动 A 的 `web/`，不碰 B。**

## 4. 分阶段路线（Phase 1 本轮，其余排期）

- **Phase 1 · 训练闭环 + UX（本轮）**：G1–G6。让一节课能「真正做完并被记录」，换设备能续。

## 5. Phase 1 实施批次（逐批交付，每批走护栏验证门）

- **Batch 1（先做）**：G1 RolePlay 讲师点评接真实数据 + G3 课末收束卡（含 `lesson_completed` 事件 + 本课小结）。自包含、风险低、闭环价值最高。
- **Batch 2**：G2 动作级步骤完成（听/读/录/提交信号驱动 Stepper 勾选）。
- **Batch 3**：G4 step 与动作完成同步服务端事件 + `/me`「继续上次」跨设备续学。
- **Batch 4**：G5 空/错/成三态统一 + G6 回流页推荐位收口。

每批验证门（护栏要求）：`ledger:snapshot before` → 改 → `ledger:check` + `typecheck` + `lint` + `build` → 浏览器 smoke 改动路由 → `ledger:snapshot after` + `diff` → commit。
**停手点**：不部署、不 push、不动 DB seed/migration、不改 B、不改 `systems/`；涉及不可逆操作先经 Ryan 批准。
