## 1. 这个项目是干什么的

**目的**：创造 / 更新 / 迭代 / 优化「SAP 项目日语培训」的**课程内容**与**自媒体内容**。

**北极星**：让中国 SAP 顾问的 SAP 实力，透过日语和文化这层壁，被日本现场正当评价。
日语是手段不是目的。课程是「训练课」不是「讲解课」，强制五动作：**听·读·换·演·录**。

**重心**：课程 与 自媒体**并重**（Ryan 2026-06-10 确认）。

**升级路线**（来自 `_instructions.md`）：先做透 SAP 项目日语培训 →
SAP 初级顾问 → 中级顾问 → AI 顾问培养。当前全力聚焦第一个。

## 5. 课程工作流（创造 / 迭代一课）

**默认产线 = V4 24 课讲师聚焦版**（已对接网站）。一课的标准成品包结构（10–12 文件）：

```
output/lesson_NN_v4_teacher_focused/
├── 00_START_HERE_FOR_TEACHER.md          # 讲师统一入口
├── 01_teacher_core/                      # 逐页逐字稿（按学生 PPT 页码）
├── 02_student_materials/                 # 学生 PPT outline / 讲义
├── 03_classroom_practice/                # 课堂练习 + RolePlay
├── 04_case_pack/                         # FICO/MM/SD/Basis/ABAP-BTP 替换素材
└── 06_management/                        # 讲师可用性质量检查
```

步骤：
1. 读该课 prompt：`sap_jp_training_course/prompts_v4/single_lessons/lesson_NN_v4_codex_prompt.md`
2. 读风格/交付标准：`SAP日语培训/03_风格手册/`、`SAP日语培训/04_交付标准/01_每课交付物清单.md`
3. 按 `templates_v4/lesson_v4_teacher_focused_template.md` 产出
4. **质量门**：来源配对、日语自然度抽查、`06_management` 质量检查；SAP 事实核实或标 `Need Confirmation`
5. 成品 MD 是真相源，PPT/docx 由对应 skill 渲染（pptx / docx），不手填
6. 更新 `state/sap_jp_training_course.json` + 写 `inbox/handoff-*`

**日语红线**：自然、能在真实日本 SAP 项目现场使用；避免课本腔/直译腔；
中文讲师指导与日文学员输出分开，不混。

## 6. 自媒体工作流（待标准化 — 本次留好挂载点）

**素材源**（不回读原始逐字稿，省 token）：
- 选题总库：`SAP-Japan-Training-Vault/12_AI养料_自媒体素材/_自媒体素材汇总.md`（按 P1–P7 支柱分组）
- 单课养料：各课逐字稿第 6 节「AI 养料」（43 课 = 43 个素材点）

**建议产线（一稿多投）**：
1. **选题** → 从素材源挑 1 个支柱痛点（如「日本人说『わかりました』≠ 同意」）
2. **主文（公众号）** → 专业、可执行、口语化；面向自媒体读者讲，但术语按专业读者水平（New GL / 并行分类账 / CO-PA / ML 物料账不从零解释）
3. **派生** → 主文 → 小红书笔记（钩子 + emoji 排版 + 话题标签）/ 视频号脚本（分镜 + 字幕时间码 + 封面文案）/ B 站
4. **真实性** → 涉及真实公司/人物不杜撰引语；SAP 商标、德国总部图等版权素材不生成
5. **现状类信息**（SAP 版本特性 / 价格 / 政策 / 新闻）先联网检索再写，不凭记忆给过时信息

> 注意：本 project 的自媒体 = **SAP 项目日语培训**主题（顾问赴日语言战斗力）。
> 与 Ryan 另一条「SAP 早报 / Walldorf 来信」财经新闻线（见全局 CLAUDE.md K–AA 节）是**不同产品**，
> 风格、品牌、产线都不共用，勿混。

## 7. 语言与文档规则

- 默认中文交流；说明类 `.md`（handoff/need-input/README/指南/审计/QA/prompt/state 说明）用中文。
- 保持日文/英文的只有：用户明确要日文输出；课程必须自然的日语学习内容/例句/对话/口播；
  代码标识、文件名、路由、命令、环境变量、SQL、API 名、错误码、专有名词、外部英文原文。
- 交付前检查本轮新增/改动的 `.md`，说明主体若是英文先改中文。

## 8. 交付纪律

- 能自己做的自己做；做不了的主动想办法（装工具 / 调 skill / computer-use），方案先说明再执行。
- 交付时状态三选一并明确写「下一步是谁的动作」：
  ①「我已做完 X」 / ②「我需要你授权 Y，批准后我自己做 Z」 / ③「请你自己跑 Y（解释为什么我做不了）」。
- 有意义工作完成 → 更新 `state/` + 写 `inbox/handoff-<topic>-<date>.md`（scope / 改动文件 / 验证 / 未跑项 / 阻塞 / 下一步）。
- 不确定目标/边界/凭据/事实 → 停手写 `inbox/need-input-<topic>-<date>.md`，不猜。

## 9. 网站 A/B 双版本接手规则

如果任务涉及 `web/`、`sap-jp.training`、Insight Desk 里的 `日语A本地 / 日语B备份`，先读：

- `docs/sap-jp-training-site-a-b-handoff_20260610.md`
- `inbox/handoff-insight-desk-training-sites-20260610.md`

当前默认认知必须一致：

- **A = 本地开发中的升级版主线**，路径 `web/`，本地入口 `http://127.0.0.1:3214/`
- **B = 已发布公网版的本地静态备份**，公网源 `https://sap-jp.training`，本地备份入口 `http://127.0.0.1:7788/sap-jp-training-public-backup/index.html`
- 用户消息里写的 `sap-jp.trainning` 当前不是实测有效域名，不能当真相源

做网站相关工作时默认策略：

1. 新功能、体验升级、训练闭环补强，都优先继续做在 A
2. B 主要用于对照、回看、备份，不当主开发线
3. 不把“本地已接入 Insight Desk”误写成“已完成公网替换”
4. 若要推进 A 替换公网 B，必须把部署、环境变量、数据迁移、生产 smoke 单列出来，经用户明确批准后再动
