### C. 交付物与问题管理术语

| 中文 | 日本项目常用日语 | 用法提醒 |
|---|---|---|
| 需求定义书 | 要件定義書 | 记录业务要件、系统要件、范围、前提和未决事项。 |
| 业务流程图 | 業務フロー | 用于说明 As-Is / To-Be，不是单纯操作截图。 |
| Fit-Gap清单 | Fit-Gap一覧 | 每个差异都要有对应方针、担当者和决策状态。 |
| 功能规格书 | 機能仕様書 | 面向功能/开发；不要把口头需求当成已承认规格。 |
| 配置定义书 | カスタマイズ定義書 / 設定定義書 | 说明配置值、理由、影响范围、测试观点。 |
| 测试用例 | テストケース | 必须有前提、步骤、期待结果、测试数据。 |
| 证迹 | エビデンス | 截图、日志、输出文件、执行时间都可以成为证迹。 |
| 缺陷票 | 不具合票 / 障害票 | “障害”偏系统故障，“課題”偏管理问题或待解决事项。 |
| 课题管理表 | 課題管理表 | 记录担当者、期限、状态、阻塞、下一步。 |
| 移行计划 | 移行計画書 | 包含作业顺序、窗口、负责人、检查点。 |
| 回退计划 | 切戻し計画 | 上线失败时如何恢复；上线判定会必须确认。 |
| 暂定处理 | 暫定対応 | 先恢复业务或降低影响，不代表根本解决。 |
| 恒久处理 | 恒久対応 | 从根因上修正，通常需要设计/配置/程序/流程变更。 |
| 再发防止 | 再発防止策 | Lesson 24 的核心，必须包含原因、对策、确认方法。 |
