# 项目目标与处理原则

## 1. 项目目标

将已整理好的 **24 次 SAP 英文培训课逐字稿 + 总结稿**，改造成一套面向中国 SAP 顾问的 **SAP 日本项目实战日语培训体系**。

最终课程要让学员能够在日本 SAP 项目中完成以下任务：

1. 用日语介绍自己的 SAP 模块、项目经验和职责范围。
2. 用日语指导用户登录 SAP GUI、输入 T-code、查看字段、截图反馈问题。
3. 用日语主持会议、确认议程、引导发言、总结行动项。
4. 用日语进行需求访谈，确认 AS-IS、TO-BE、pain point、expected output。
5. 用日语说明 SAP 实施阶段：kickoff、要件定義、設計、設定、テスト、UAT、本番稼働、稼働後サポート。
6. 用日语解释 SAP 配置、主数据、事务数据、接口、测试、问题处理。
7. 用日语说明 P2P、OTC、RTR 等端到端流程。
8. 用日语处理 scope、追加需求、phase 2、change request。
9. 用日语写简短会议纪要、问题说明、需求确认和 follow-up。
10. 在日本项目面试或项目导入会议中，像顾问一样清楚表达价值。

---

## 2. 课程设计底层原则

### 原则一：不要逐字翻译，要做顾问能力迁移

原课是 SAP 英语培训，里面的英文表达只是线索。日语版要回答的是：

- 这个场景在日本 SAP 项目中会怎么说？
- 日本客户/用户能不能听懂？
- 这句话是否自然、礼貌、可推进工作？
- 学生能不能拿去会议里直接使用？

错误做法：

```text
login = ログインする
logout = ログアウトする
```

正确做法：

```text
まず SAP GUI を起動してください。
次に、クライアント、ユーザー ID、パスワードを入力します。
ログイン後、コマンドフィールドに T コードを入力してください。
```

---

### 原则二：每个知识点都要变成顾问动作

每个术语都要放进真实项目动作里：

| 层级 | 要求 |
|---|---|
| 词 | 知道 SAP / 日语术语 |
| 句 | 能说一句项目现场能用的话 |
| 场景 | 能和用户、顾问、PM 互动 |
| 输出 | 能完成 30 秒或 60 秒顾问说明 |
| 交付 | 能写会议纪要、需求确认、测试说明、问题汇报 |

---

### 原则三：每个 SAP 场景都用 Input → System Action → Output

示例：采购流程。

```text
Input:
購買依頼、仕入先、品目、数量、価格などを入力します。

System Action:
システム上で購買発注を登録し、入庫後に会計伝票が自動生成されます。

Output:
最終的に請求書照合を行い、支払処理につなげます。
```

---

### 原则四：每课必须有可开口训练

每课至少包含：

- Shadowing
- Substitution Drill
- 30 秒 Micro Training
- Role Play
- 会议/邮件/问题处理小输出
- 作业
- 讲师点评标准

---

### 原则五：日语表达必须符合日本项目现场

日语版不是普通日语课，必须包含日本项目文化：

| 日本项目能力 | 训练重点 |
|---|---|
| 丁寧語 | です・ます、いたします、お願いいたします |
| 報連相 | 報告・連絡・相談 |
| 認識合わせ | 确认理解，避免误会 |
| 議事録 | 会议纪要、宿題、担当者、期限 |
| 根回し | 会议前协调关键干系人 |
| スコープ確認 | 范围内/范围外/追加需求 |
| 仕様確認 | 规格、需求、系统行为确认 |
| 障害報告 | 问题、原因、影响、暂定应对 |
| 催促 | 礼貌推进任务 |

---

## 3. Codex 必须遵守的判断标准

每一课完成后，用下面的问题检查：

1. 是否抓住了原课主题？
2. 是否保留了 SAP 顾问场景？
3. 是否没有机械翻译英文？
4. 是否把英文课转成了日本项目现场自然表达？
5. 是否有可开口练习？
6. 是否有新的“日语课堂逐字稿”？
7. 是否有学生可复用的术语表和句型库？
8. 是否有 ASR 待复核清单？
9. 是否清楚区分了“原课内容”和“日语课程扩展内容”？
10. 是否让学生更像一个 SAP 顾问，而不是只像背单词的人？
