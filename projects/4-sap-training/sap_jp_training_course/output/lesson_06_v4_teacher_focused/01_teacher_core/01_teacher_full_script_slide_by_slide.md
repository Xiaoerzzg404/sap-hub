## S-Slide 02：这节课解决什么 SAP 项目痛点

### 1. 本页目标

让学生看到本课与 SAP 项目交付直接相关。

### 2. PPT 页面展示内容摘要

很多顾问懂自己模块，但无法用日语解释“谁把什么数据传给谁、从哪里起点、经由哪里、在哪边管理”。

### 3. 讲师口播稿：中文

很多顾问懂自己模块，但无法用日语解释“谁把什么数据传给谁、从哪里起点、经由哪里、在哪边管理”。

如果表达过硬，客户可能觉得你不配合；如果表达过软，项目风险又说不清。所以我们训练的不是“更客气”，而是让礼貌服务于项目推进：该确认的确认，该说明的说明，该给下一步的给下一步。

### 4. 讲师口播稿：日语示范

この場面では / 丁寧さだけではなく、/ 役割、前提、次の対応を / 明確にすることが重要です。
製造実績は / MESからSAPに連携されます。
SAPプロジェクトでは / 表現の自然さと / 作業の進め方を / 同時に伝える必要があります。

### 5. 讲师领读设计

- 製造実績は / MESからSAPに連携されます。
- 前提を / 確認いたします。
- 次の対応を / 明確にします。

### 6. 学生练习 / 提问

请学生说：这个场景里，如果表达不稳，会造成什么项目风险？

### 7. 学生可能回答

- 客户误解为已经承诺。
- 会议目的不清。
- 责任范围不清。
- 后续行动没有被记录。

### 8. 讲师点评与纠错话术

点评重点不是日语语法，而是项目风险：误解、过度承诺、边界不清、下一步不清。

### 9. 本页常见中式日语错误

错误：只追求句子礼貌，不说明项目动作。改法：每一句都要带出角色、对象、期限或下一步。

## S-Slide 07：为什么这个表达习惯很重要

### 1. 本页目标

解释文化与项目交付的关系。

### 2. PPT 页面展示内容摘要

日本项目中表达习惯服务于信任、确认和协作。

### 3. 讲师口播稿：中文

日本项目里，表达方式经常会影响推进速度。不是因为大家只看形式，而是因为会议参与方多、责任边界细、客户和顾问之间需要长期合作。表达太直接会让讨论停止；表达太模糊会让风险积累。

所以本课的文化点，要落到项目动作：系统定位 → 数据起点 → 传输方向 → 管理侧 → 业务影响。只要你能按这个顺序说，礼貌就不再是表面功夫，而是推进项目的工具。

### 4. 讲师口播稿：日语示范

丁寧に話すことは / 目的ではありません。
誤解を減らし、/ 次の対応を明確にするために / 表現を整えます。
製造実績は / MESからSAPに連携されます。

### 5. 讲师领读设计

- 誤解を減らします
- 次の対応を明確にします
- 製造実績は / MESからSAPに連携されます。

### 6. 学生练习 / 提问

问学生：礼貌表达和项目推进有什么关系？

### 7. 学生可能回答

- 客户更容易接受风险说明。
- 会议目的更清楚。
- 后续行动更容易确认。

### 8. 讲师点评与纠错话术

强调：礼貌不是软弱，而是让专业判断被听进去。

### 9. 本页常见中式日语错误

错误：把礼貌理解成不说风险。改法：用礼貌结构说清风险和下一步。

### 10. 过渡到下一页的话术

## S-Slide 09：五步表达结构

### 2. PPT 页面展示内容摘要

### 3. 讲师口播稿：中文

现在把主线固定成五步。每一步都不要太长，但不能缺。缺第一步，语气会突然；缺中间步骤，项目对象不清；缺最后一步，客户不知道下一步。

待会儿所有 Roleplay 和录音作业都按这五步来。你可以先用中文列点，再把日语句子填进去。

### 4. 讲师口播稿：日语示范

次に / 起点。
その後 / 連携先。
最後に / 業務影響まで伝えます。

### 5. 讲师领读设计

- 最後に / 業務影響

## S-Slide 10：高频词汇 1：基幹システム / 周辺システム / インターフェース
