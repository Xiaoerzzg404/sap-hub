# Project 3 · SAP 内容生产（公众号 + 视频号 + 小红书）

## 不可破坏的前提
公众号日更、视频号日更**已稳定运行**（在 ~/news/studio，软链于 systems/
media-pipeline）。这是已有成果，**禁止破坏**。本 Project 只做“加法”，
任何改动先并行验证一周，产物一致才切换。

## 两个目标
1. **合并**：公众号与视频号现分散在不同文件夹，收敛到统一目录约定与
   共享主文，不再各算各的。
2. **省 token**：日更最大成本是重复调用大模型。用“一次主文 + 下游派生”
   + 模型分级，把成本降到 1/2 ~ 1/3。

## 省 token 编排（核心规格）
```
[抓取/清洗/去重]        → 便宜模型(Haiku 级)
        ↓
[主文：财经新闻体一次成稿] → 中端模型(Sonnet 级)   ← 唯一一次“深度生成”
        ↓
[公众号定稿]  ← 主文轻整理（同 Sonnet，小改）
[视频号脚本]  ← 从主文派生改写（Sonnet 轻调，不重新分析）
[小红书笔记]  ← 从主文派生改写（同上）
[封面/卡片]   ← 模板渲染，零模型
[难选题/深度] ← 偶尔 Opus，仅在该期确实值得
```
铁律：**主文只生成一次；下游一律“改写/裁剪”，禁止对同一素材重复深度分析；
HTML/卡片一律模板渲染不走模型。**

## 合并落地（执行体在本地做，需先读现有实现）
本规格给方向，**精确实现前执行体必须先读 ~/news/studio 现有脚本**
搞清楚：现在各环节实际调用哪个模型、公众号与视频号在哪分叉。
读完在 `state/merge-plan.json` 写出“现状→目标”映射，经用户确认后再改。
**不确定不许猜，走 inbox/need-input。**

## 统一目录约定（目标态）
```
projects/3-sap-content/
├── state/
│   ├── daily/<YYYY-MM-DD>.json   # 当日：主文状态 + 三平台派生状态 + 用了哪些模型
│   └── merge-plan.json           # 合并的现状→目标映射（执行体读现有实现后填）
├── knowledge/
│   ├── master/<YYYY-MM-DD>.md    # 当日主文（唯一真相）
│   ├── templates/                # 三平台模板 + 封面模板
│   └── style/                    # 财经新闻体 / 口语种草 文体样本
```

## 产出纪律
- 主文：财经新闻体，无 emoji、无第一人称、记者笔法，来源可点击。
- 小红书派生：口语、钩子开头、话题标签。
- 真实公司/人物不杜撰引语；不生成 SAP 商标等版权素材。

## 给执行体的明确边界
本轮只允许：建目录约定、写 merge-plan 草案、并行验证脚本。
**不允许**：在未经用户确认 merge-plan 前改动现有日更流水线。
